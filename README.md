# MeetingShot-for-Mac v0.4 — 方案二 MVP
使用方法：下载zip文件后右键打开“安装并打开MeetingShot.command”，等待一会即可启用。
注意Mac的app图标可能在屏幕顶端的工具栏。

这是用于验证“画面变化触发截图”核心逻辑的 macOS 测试版本。

## 核心逻辑

1. 用户手动点击“开始截图”。
2. 窗口自动隐藏，等待 3 秒。
3. 保存第一张高清截图，并建立画面基准。
4. 之后每 1 秒读取一次主显示器画面，将主屏中央 84% 区域缩小为 `120 × 68` 灰度图进行比较。
5. 检测到明显变化后，等待画面稳定约 1 秒。
6. 若稳定后的画面与最近一次已保存画面存在明显差异，则保存一张高清截图。
7. 无论是否检测到变化，每 30 秒强制保存一张兜底截图。
8. 用户手动点击“停止截图”结束。

截图文件名会注明触发原因：

- `首次`：开始后的第一张；
- `变化`：画面变化稳定后自动保存；
- `兜底`：30 秒强制保存；
- `手动`：用户点击“立即补截”。

例如：

```text
0001_16-35-03-125_首次.png
0002_16-35-11-421_变化.png
0003_16-35-41-803_兜底.png
```

## 安装

解压后双击：

```text
安装并打开MeetingShot.command
```

应用安装位置：

```text
~/Applications/MeetingShot.app
```

应用会替换此前安装的 MeetingShot，但不会删除原有截图文件。

## 屏幕录制权限

首次运行或版本替换后，macOS 可能要求重新确认权限：

```text
系统设置 → 隐私与安全性 → 屏幕与系统音频录制
```

如果系统设置中已开启但应用仍提示无权限：

1. 完全退出 MeetingShot；
2. 关闭并重新打开 MeetingShot 的权限开关；
3. 从 `~/Applications/MeetingShot.app` 重新启动。

必要时可在终端运行：

```bash
tccutil reset ScreenCapture com.frank.meetingshot
```

然后重新打开应用并授权。

## 建议测试方法

先不要直接用于重要会议。建议用本地 PowerPoint 或 PDF 做一次 5～10 分钟测试：

1. 打开一份 PPT 并进入放映模式；
2. 启动 MeetingShot，点击“开始截图”；
3. 分别测试正常翻页、快速翻页、动画、鼠标移动和长时间停留；
4. 点击“停止截图”；
5. 检查文件名中“变化”和“兜底”的数量，并确认是否漏页或误截。

同时可在“活动监视器”中观察 MeetingShot 的 CPU、内存和能耗。

## 当前限制

- 只分析并保存主显示器，不识别腾讯会议窗口。
- 不框选 PPT 区域。
- 鼠标移动通常不会触发，但大面积视频、动态背景、弹窗或腾讯会议界面变化可能被判断为画面变化。
- PPT 动画会被视为画面变化；程序会等待动画停止约 1 秒后保存，但复杂动画仍可能产生多张截图。
- 使用兼容旧版 macOS/Swift 的 Core Graphics 截屏方式。虽然比较的是低分辨率图，但每次分析仍需要先读取主显示器画面；本版本的目的之一就是实测资源占用。
- 变化阈值是 MVP 初始值，需要根据实际测试结果继续调整。

## 构建环境

- Swift 5 兼容语法；
- 最低 macOS 10.15；
- 适配用户当前的 Apple Swift 5.4 命令行工具；
- 原生 AppKit 应用，无网络上传、无麦克风或摄像头访问。
